# 11 — Measurable wall metric: active wall to the solver gate

**What to build:** The wall-time acceptance axis becomes computable. Definition locked in the planning session: **active wall = Clarification session start → the user's Review-gate approval to start the EM solver** (solver physics, idle gaps, and post-solve time are out — they are machine time and user time, not agent time). The measurement harness records both boundary timestamps — the ledger's session-1 start, and the solve submission instant — and reports raw wall and active wall side by side. The acceptance gate compares active wall only where the baseline run's build-to-solver window is derivable the same way; otherwise wall is reported informational and the go/no-go rests on the two exact axes (billed tokens, parts).

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

- [x] Session start timestamp written to the ledger by the Clarification session
- [x] Solver submission instant recorded when the user-gated submission happens
- [x] Run card reports raw wall and active wall (start → solver gate) side by side
- [x] Verdict table uses active wall when the baseline is derivable; otherwise marks wall informational (reported, never gated on an uncomputable number)
