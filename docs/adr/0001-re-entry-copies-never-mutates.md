# Re-entry works on a copy, never the original project

Re-entry conversations (open an existing model, change it, re-solve) begin by copying the original `.aedt` (results folder included) into the conversation's workspace as a plain filesystem operation. Introspection, reporting, and all changes then happen on the copy; the user's original `.aedt` is never opened or mutated. (`duplicate_design` was considered and rejected: it copies a design *within the same project file*, so the next save would mutate the original it was meant to protect.) Cost: an extra copy step, disk for results, and a bigger conversation. Reason: a user's existing project — often not AI-created and not reconstructable from scripts — must stay pristine; a wrong AI-driven edit (e.g. invalidating a radiation/port assignment during an antenna→RCS pivot) would otherwise leave the original broken with no way back.
