# Staged scripts re-sync after UI tweaks; all geometry is parameterized

ADR 0003 makes the AEDT UI the review surface — the user tweaks the model there — while also claiming the staged scripts in `src/` are "an archival, re-runnable record". Both can only hold if the scripts are brought back in line with the tweaked state. Decision: after any user UI tweak, the agent introspects the live model via pyAEDT (design variables, boundaries, excitations, setups, mesh operations are all enumerable) and amends the *owning stage's* staged script, so re-running the scripts top-to-bottom reproduces the delivered model; the delta is recorded in `summary.md` and feeds the learning loop. Enabling convention: all geometry is built with design variables, so most UI tweaks are variable-value edits — trivially readable and syncable. Considered options: appending a separate amendment script was rejected (the record becomes a palimpsest — reproducing means folding an override file back through every stage); accepting divergence was rejected (it silently retires the re-runnability property, and the final state would exist only inside the `.aedt`). Consequences: the learning loop gets its tweak delta mechanically rather than by interrogation, and re-entry edits become variable changes; the cost is a standing discipline that every staged script is fully parameterized and that no review gate closes until sync has run.
