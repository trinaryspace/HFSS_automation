# Solves run under a deterministic detached watchdog — amended: stage-aware, evidence-before-claiming, banked before teardown

The solve stage means the agent launching `analyze(blocking=False)` once per verified state and then never touching the solve again: no LLM babysitting, no foreground polling, no solve-time estimation. Two deterministic scripts own the lifecycle: the launcher submits and starts a detached `poll_solve.py` that appends one line per ~20 s tick to the solve-progress state file and exits on a terminal state; the agent does nothing but read that file. Terminal states are evidenced, never guessed: **complete** (the solve profile's `Status` says "Normal Completion" and the sweep settled), **stalled** (no growth in the current stage past its window — the stage is named in the evidence), **aborted** (in-flight markers gone, no completion, solver process dead). The watchdog never claims done or stalled without appending the profile's Status line, and completion never depends on a predicted output count — the sweep-point guess class is removed. Stage detection (initial meshing → adaptive meshing → frequency sweep) reads the profile's stage ledger plus stage-family artifact growth, so a mesh stuck forever and a running sweep never look alike. The watchdog imports nothing from pyAEDT — filesystem and process observation only. After a terminal line, a post-solve confirm **banks** the solve evidence (status + sweep count) to the machine state; teardown closes a banked workspace with projects left on disk (`close_projects=False`), refuses an unbanked workspace that shows solve evidence, and behaves as before where nothing was solved. Considered options: a background cheap-model subagent was rejected (tokens per poll for zero gain over a stateless script); lengthening the bash timeout was rejected as the sole fix (it fixes the cap, not the attention cost of polling from a fat context); settle-mode-only completion was rejected after it declared an engine-error plateau complete (ticket-06 pilot); teardown-anytime was rejected after it purged a solved project's results (ticket-06 pilot). Consequences: solve watching costs ~0 LLM tokens, results survive teardown, and the false-stall/false-complete and results-purge incident classes are structurally closed; the pre-submit guard and the idempotent-stage doctrine (ADR 0008) are untouched.
