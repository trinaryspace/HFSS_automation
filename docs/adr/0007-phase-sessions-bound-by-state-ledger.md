# Conversations run as three phase sessions bound by the State ledger

One conversation used to mean one agent session held from Clarification to summary — measured at 152 steps with no compaction, ~260 k tokens re-read every step (39.2 M cache reads), which is the dominant cost of the tool (2026-08-02/03 runs). Decision: a conversation is three named sessions — (1) Clarification, which locks the Recipe/Assumptions/QA-signals and writes the **State ledger**; (2) Build through the Review gate including read-back sync, appending to the ledger; (3) Solve+QA, which reads the ledger and delivers summary.md + the run card. Each session starts fresh, carrying only `workspaces/<name>/state.md` (stage progress, locked parameters/variables, pitfalls, model-snapshot pointer) plus the relevant staged scripts; machine state stays in `results/state/*.txt`. Considered options: one session with `/compact` at the gates was rejected (compaction preserves the transcript at best-effort and keeps cross-session drag; the ledger is exact and tiny), and per-stage sessions were rejected (fourteen handoffs for no gain — the hardening boundaries are the gate and the solve, exactly two). Consequences: a killed session resumes from the ledger instead of redoing Clarification and script-writing; the ledger is a byproduct that also feeds the run card and summary; the discipline cost is that every stage must append its one-line ledger delta.
