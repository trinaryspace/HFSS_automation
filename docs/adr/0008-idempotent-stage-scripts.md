# Staged scripts are idempotent: delete-then-create

The deterministic-build doctrine said "fresh project or exact rebuild" — with the observed consequence that every failed stage run left same-name duplicates on the dirty project (the EC#8 trap) and the only escape was teardown → wipe → rerun chains, three of them in one build, each costing AEDT launches and reruns. Decision: the build doctrine is idempotent stage scripts — every script deletes the objects, boundaries, excitations, mesh operations, and sweeps it (re)creates before creating them, so re-running any stage in place always converges; wipe-and-rebuild is demoted to an explicit escalation tool, not the default. Considered options: building everything under fresh unique names was rejected (names must stay stable for the read-back sync contract, ADR 0005), and keeping wipe-and-rebuild was rejected (it turns every self-correction round into a full-chain replay). Consequences: self-correction becomes a single re-run in place; the environment-compat EC#8 route-around is rewritten to match; delete calls are exercised on every re-run, so stale-object bugs surface early.
